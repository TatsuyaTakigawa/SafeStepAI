1　概要

1.1　目的

本仕様書は、SafeStep AI（学校階段逆走検知・音声警告システム）のソフトウェア要求を定義することを目的とする。

本校では昼休みに階段の一方向運用を実施しているが、掲示物のみによる周知では遵守率が低く、逆走による衝突・渋滞が断続的に発生している。本システムは映像AIを用いて逆走を自動検知し、音声警告によって逆走率を低下させ、衝突事故を未然に防止する。

1.2　位置づけ

本書は SafeStep AI プロジェクトにおけるソフトウェア要求仕様書（SW105）であり、本システムの要求事項および設計方針を定義する文書である。

参考事例として、福岡市地下鉄にて実証された来栖川電算「エスカレーター見守り君」と同様のアプローチを、学校階段向けに低コスト化・最適化したシステムとして位置づける。

1.3　対象ユーザ

以下のユーザが本システムの対象となる。

- 階段を利用する生徒（主な逆走抑止対象）

- 階段を利用する教職員

- システム管理者（設定・保守担当者）

1.4　記載範囲

本書の記載範囲は以下の通りである。

- 映像取得・前処理モジュール

- 人物検出・追跡モジュール（YOLO + SORT）

- 逆走判定モジュール

- 音声警告制御モジュール

- ログ・統計出力モジュール

なお、ハードウェア（Raspberry Pi 5、カメラ、スピーカー）の物理設置・配線については、別途ハードウェア仕様書に委ねる。

2　システム構成

2.1　システム全体構成

本システムはエッジ処理型のシングルボードコンピュータ構成を採用し、外部ネットワーク接続なしにすべての推論処理をデバイス内で完結させる。

【システム構成概略】

| **レイヤ** | **構成要素** | **処理内容** |
| --- | --- | --- |
| 入力層 | 俯瞰カメラ（カメラモジュール） | 階段通行者の映像取得（リアルタイム） |
| 処理層 | Raspberry Pi 5（8GB）/ Python / OpenCV / YOLO / SORT | 人物検出・追跡・逆走判定・警告制御 |
| 出力層 | USB スピーカー | 音声アナウンスの再生（3パターンランダム） |
| 保存層 | （なし） | 映像データは一切保存しない（プライバシー保護設計） |

*※ **映像は推論処理のみに利用し、ストレージへの書き込み・外部送信は行わない。*

| C-06 | 個人識別禁止 | トラッキングは方向判定に限定し、個人特定に利用しない |

6　機能詳細

6.1　F-01 映像取得・前処理

| **項目** | **内容** |
| --- | --- |
| 入力 | 俯瞰カメラ映像（リアルタイムストリーム） |
| 処理 | OpenCV にてフレームを取得し、YOLO 推論用サイズにリサイズ・正規化 |
| 出力 | 前処理済み映像フレーム（YOLO 入力テンソル） |
| 制約 | 映像フレームはメモリ上のみで処理し、ストレージに書き込まない |

6.2　F-02 人物検出・追跡（YOLO + SORT）

| **項目** | **内容** |
| --- | --- |
| 入力 | 前処理済み映像フレーム |
| YOLO 処理 | 人物クラス（person）のバウンディングボックスと信頼度スコアを出力 |
| SORT 処理 | カルマンフィルタと IoU マッチングにより、フレーム間で同一人物を追跡 |
| 仮想ライン | 映像内に設定した水平または垂直の仮想ラインを通過方向で逆走を判定 |
| 出力 | 各トラックの ID・位置・進行方向（順走 / 逆走）フラグ |

6.3　F-03 逆走判定・警告制御

| **項目** | **内容** |
| --- | --- |
| 入力 | 各トラックの進行方向フラグ |
| 判定ロジック | 逆走フラグが立ったトラック数を累積。設定閾値（デフォルト：3人）を超えた時点で警告トリガーを発行 |
| 警告慣れ防止 | 音声パターンを3種類用意し、毎回ランダムに選択して再生 |
| クールダウン | 連続警告を防ぐため、発報後は設定秒数（デフォルト：30秒）のクールダウンを設ける |
| 出力 | USBスピーカーへの音声再生コマンド |

6.4　F-04 ログ・統計出力

| **項目** | **内容** |
| --- | --- |
| 記録項目 | タイムスタンプ、階段利用者数、逆走カウント数、警告回数、逆走割合 |
| 出力形式 | CSV ファイル（ローカルストレージ） |
| 活用目的 | 導入前後の効果比較、閾値最適化、フレームレート計測データとして利用 |
| 映像保存 | なし（映像フレームはログに含まない） |

9　その他

9.1　効果測定・調査計画

本システム導入の効果を定量的に検証するため、以下の指標を測定する。

| **指標** | **測定方法** | **計測タイミング** |
| --- | --- | --- |
| 逆走率 | 逆走人数 / 総通行人数 × 100（%） | 昼休みごと（導入前後で比較） |
| 警告回数 | ログから警告イベント数を集計 | 昼休みごと |
| 逆走人数 | 逆走カウントのログ集計 | 昼休みごと |
| 推論フレームレート | FPS ログの平均・最小値 | 混雑時・非混雑時それぞれ計測 |
| 誤検知率 | 正常通行者への警告数 / 総警告数 | 観察者による目視確認と併用 |

検証ステップは以下の順序で実施する。

- ステップ1：導入前2週間のベースライン計測（人力目視）

- ステップ2：システム試験稼働（1週間）・パラメータ調整

- ステップ3：本稼働（2週間以上）・定量比較分析
