１．プロジェクト概要

1.1　プロジェクト名

SafeStep AI

1.2　背景・課題

本校の階段は昼休み時間帯において混雑緩和を目的とした一方通行ルールを設けている。しかし、以下の問題が継続的に発生している。

- ルールを知らない生徒・教職員による逆走

- ルールを認識しているにもかかわらず遵守しない者による逆走

- 逆走者と正規方向通行者の接触・衝突リスク

- 昼休み時間帯の階段付近における慢性的な渋滞の発生

1.3　プロジェクトの目的

カメラ映像を用いたAI技術により、階段上の人物をリアルタイムで検出・追跡し、逆走行動を自動検知する。検知時には即座に音声アナウンスを行うことで、逆走者への注意喚起および周辺者への安全確保を促進する。

1.4　目標

- 逆走検知システムの安定稼働（昼休み時間帯：12:45〜13:30）

- 導入前後における逆走件数の比較による効果測定

- ルール遵守率の向上（具体的な数値目標は運用後のデータをもとに別途設定）

２．システム概要

2.1　システム構成概要

本システムは、Raspberry Pi 5をコアとするエッジコンピューティング構成を採用する。各階段に独立したRaspberry Piユニットを設置し、それぞれが単独で人物検出・追跡・逆走検知・アナウンス出力を完結する分散型アーキテクチャとする。

2.2　システム構成図

2.3　ハードウェア構成

| **機器** | **型番・仕様** | **数量** | **備考** |
| --- | --- | --- | --- |
| Raspberry Pi | Raspberry Pi 5 / 8GB | 4台以上 | 既存機器を活用 |
| カメラ | 学校既存WEBカメラ | 各Pi 1台 | 性能・フレームレート要確認 |
| スピーカー | USB/3.5mmスピーカー | 各Pi 1台 | 新規購入必要 |
| ネットワーク | Wi-Fi / 有線LAN | 各Pi | 学校既存環境を活用 |

2.4　ソフトウェア構成

| **機能** | **使用技術・ライブラリ** | **備考** |
| --- | --- | --- |
| 人物検出 | YOLO（軽量モデル） | リアルタイム処理に最適化 |
| 人物追跡 | SORTアルゴリズム | IDベースの連続追跡 |
| 逆走検知 | 仮想ライン判定ロジック | カメラアングルに応じて設定 |
| 音声アナウンス | 事前収録音声ファイル再生 | pygameまたはaplay等 |
| スケジュール管理 | Cron（時間指定起動） | 12:45〜13:30のみ稼働 |
| ログ管理 | CSVまたはSQLiteによるローカル保存 | 映像は保存しない |
| 管理画面 | Webダッシュボード（Flask等） | 統計・ログ閲覧 |

2.5　クラウド連携（条件付き）

Raspberry Piの処理能力がYOLO+SORT+逆走検知の同時実行に不足する場合、AWSまたは同等のクラウドサービスとの併用を検討する。その際、Raspberry Piはエッジデバイスとして映像キャプチャと前処理を担い、推論処理をクラウドにオフロードする構成とする。

2.6　ネットワーク構成

各Raspberry Piは学校内ネットワーク（Wi-Fi または 有線LAN）に接続し、管理サーバーとログ・統計データを同期する。映像データはネットワーク上に送出しない。

３．機能要件

3.1　主要機能一覧

| **No.** | **機能名** | **概要** | **優先度** |
| --- | --- | --- | --- |
| F-01 | 人物検出 | カメラ映像からYOLO軽量モデルにより人物をリアルタイム検出する | 必須 |
| F-02 | 人物追跡 | SORTアルゴリズムにより各人物にIDを付与し継続的に追跡する | 必須 |
| F-03 | 逆走検知 | 仮想ラインを用いて人物の通行方向を判定し逆走を検知する | 必須 |
| F-04 | 音声アナウンス | 逆走検知時に事前収録音声を即時再生し注意喚起する | 必須 |
| F-05 | ログ記録 | 逆走検知日時・件数等をローカルに記録・保存する（映像保存なし） | 必須 |
| F-06 | 時間制御 | Cronにより12:45〜13:30のみシステムを自動起動・停止する | 必須 |
| F-07 | 管理画面 | ブラウザからログ閲覧・統計グラフを確認できるWebダッシュボード | 推奨 |
| F-08 | 認証機能 | 管理画面へのアクセスをID/パスワードで制限する | 推奨 |
| F-09 | 一元管理 | 複数台のRaspberry Piの稼働状況・ログを一画面で確認できる | 任意 |

3.2　映像・プライバシー方針

- 映像はリアルタイム処理のみに使用し、ストレージへの保存は行わない

- 人物の顔情報等の個人識別情報は記録・保存しない

- 逆走検知ログには個人を特定できる情報を含まない

４．非機能要件

| **カテゴリ** | **要件** | **目標値・条件** |
| --- | --- | --- |
| 検知精度 | 誤検知率 | 0.1%以下（目標値・要検証） |

| セキュリティ | 管理画面アクセス制御 | ID/パスワード認証必須 |
| プライバシー | 映像保存 | リアルタイム処理のみ・保存禁止 |
| 設置環境 | 稼働環境 | 屋内階段（自動照明あり・人感センサー連動） |
| ネットワーク | 接続方式 | Wi-Fi / 有線LAN（学校既存環境） |
| 拡張性 | 台数追加 | モジュール構造により4台以上に容易に拡張可能 |

８．リスク／懸案事項

| **No.** | **リスク・懸案事項** | **影響度** | **発生** **可能性** | **対応策** |
| --- | --- | --- | --- | --- |
| R-01 | YOLO・SORTの習得コスト超過（チーム全員初挑戦） | 高 | 高 | 早期にチュートリアル・検証を実施。外部リソース・論文・OSSを積極活用する |
| R-02 | Raspberry Piの処理能力不足（YOLO+SORT同時実行） | 高 | 中 | 軽量モデル（YOLOv8n等）を優先採用。不足時はAWS等クラウドとのハイブリッド構成に移行 |
| R-03 | 既存カメラの性能・互換性問題（フレームレート・解像度不明） | 高 | 中 | 早期に既存カメラの仕様確認・動作テストを実施。不適合の場合は追加調達を検討 |
| R-04 | 逆走検知精度の未達（混雑時・カメラアングル問題） | 中 | 中 | 仮想ライン位置・角度の最適化。複数アングルからの検証を実施 |
| R-05 | 個人情報・プライバシー問題 | 高 | 低 | 映像の非保存方針を徹底。学校・関係者への説明と合意形成を実施 |

- Raspberry Pi 5上でのYOLO+SORT+逆走検知の同時実行可否の検証

- クラウド併用時のコスト試算と予算確認
