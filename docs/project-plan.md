# SafeStep AI プロジェクト計画書

- 版：2.0（実装状況に合わせた改訂）
- 更新日：2026年11月11日
- プロジェクト：学校階段における逆走検知・注意喚起システム

## 1. 目的

本プロジェクトでは、学校階段を対象とした逆方向通行の検知・注意喚起を行う試作システムを開発します。カメラ映像を検知端末内で処理し、仮想ライン通過方向を判定します。逆走時は音声を再生し、イベント情報をWebダッシュボードで確認できる構成を目指します。

本システムは開発中の試作であり、施設の安全設備や人員による安全管理を置き換えるものではありません。

## 2. 実装ベースライン

| サブシステム | 現在の構成 |
| --- | --- |
| 検知 | Raspberry Pi上のPython、Ultralytics YOLOトラッキング、仮想ライン方向判定 |
| 音声 | ホスト上のPythonプレイヤー、`aplay`、`pi/warning_audio/alert.wav` |
| イベント連携 | APIキー付きHTTP POST。送信項目は端末名、発生時刻、追跡ID、方向、逆走フラグ |
| ダッシュボード | PHP 8.3 + Apache。ログイン、イベント表示、端末別集計、直近24時間の分析 |
| データベース | MariaDB 11.4、単一の`events`テーブル。Composeボリュームに永続化 |
| 配備 | ダッシュボードとDBはDocker Compose。検知端末は`pi/start_safestep.sh`から実行 |

個別の検知端末とダッシュボード端末を分離して配置できます。現行コードにはクラウド連携、CSV/SQLite保存、日次統計テーブル、Cronによる運転時間制御、複数階段の稼働監視は実装済み機能として含めません。

## 3. 対象範囲

### 対象

- カメラからの人物検出・追跡と方向イベント生成
- 通常方向と逆方向の比較
- 逆走トリガーによる端末側音声再生
- API経由のイベント登録とMariaDBへの保存
- ログイン保護されたダッシュボードとイベント集計
- 実環境に合わせたパラメータ調整、機能試験、性能評価

### 対象外または未実装

- 映像の録画・保存・Webサーバーへの転送
- 顔認識、個人の特定
- 音声以外の物理的な安全制御
- 定時起動・停止機能の実装保証
- 永続送信キュー、ネットワーク復旧後の再送保証
- 複数階段・複数端末の死活監視
- 実測済みの精度、FPS、遅延などの性能保証

## 6. 評価指標

測定前に定義と試験条件を固定し、実測値を記録します。目標値を置く場合は測定結果と混同しないよう明示します。

- 方向別の試行数、正検知数、見逃し数、誤検知数
- ライン通過からアラーム開始までの遅延
- イベントAPIへの登録成功率と応答時間
- カメラ条件、照明、混雑度、遮蔽、歩行速度、試験時間
- CPU、メモリ、処理速度、連続稼働時間（必要に応じて測定）
- ネットワーク切断、プロセス再起動、DB復元時の動作

## 7. リスクと対応

| リスク | 影響 | 対応 |
| --- | --- | --- |
| カメラ位置・照明・遮蔽による誤検知や見逃し | 方向判定の信頼性低下 | 設置条件を記録し、条件別に反復試験。運用前に現地で確認 |
| Raspberry Piの処理能力や温度 | フレーム処理遅延、停止 | 実機で負荷・温度・長時間動作を確認し、冷却・電源を確保 |
| ネットワークまたはDB障害 | イベントが保存されない可能性 | API/DBログを確認し、バックアップと復元を定期検証。再送保証が必要なら別途実装 |
| APIキー・DB認証情報の漏えい | 不正登録・データ漏えい | 秘密情報をGitに登録せず、十分な強度の認証情報を使用・更新 |
| アラームが聞こえにくい／頻繁すぎる | 注意喚起の効果低下 | 実環境で音量・配置・再生間隔を確認し、利用者・施設の了承を得る |
| プライバシー・施設利用上の問題 | 設置・運用の停止 | 施設の承認、掲示・説明、適用ルールの確認を実施 |
